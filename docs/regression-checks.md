# 回归检查

使用测试存档。以下项目为待执行的游戏内检查，不代表自动测试已通过。

## 链接生命周期

1. 世界与结构、两个独立结构分别连接黄铜及安山轴。
2. 卸载其中一端所在区块超过 60 tick，再返回：物品不应掉落，加载后应恢复原有链接。
3. 对其中一端结构进行物理化、取消物理化：应在迁移后恢复链接。
4. 用镐、潜行扳手、爆炸拆端口：轴应仅回收或掉落一次，物理杆立即消失。
5. 在两个维度同时使用气动轴：动作速度不应随另一维度的轴数量或更新次数变化。

## 物理与动能

1. 气动轴分别伸长、缩短；越过碰撞体重建阈值时，观察是否突然停止、抖动或弹飞。
2. 用工具枪拖动一端，测试普通轴回弹和安山轴自由伸缩。
3. 验证轴对世界与第三方物理结构的碰撞仍有效。
4. 两端接入动力与负载，比较护目镜的网络容量、负载和过载状态；不能仅以轴是否旋转判断并网成功。
5. 拆轴、迁移后验证负载不再错误留在原网络，并且重新连接后可恢复工作。

## 收纳恢复

1. 普通收纳器收纳带外部轴的结构，确认外部轴回收一次。
2. 高级收纳器收纳含内部轴与 Sable 关节的结构组，在不同位置释放；位置、内部链接和关节均应保持正确。
3. 在单独测试环境中，让组内一个结构的加载失败：已创建结构应全部移除，收纳器内容保持原样，不产生额外轴掉落。
4. 修复失败原因后重试释放：不得重复结构或丢失内部关联。
5. 保存、重启游戏后重复上述操作，验证持久化状态。
6. 生存与创造模式分别测试背包已满时回收外部轴：物品应掉落在玩家旁，数量恰好一个。
7. 普通收纳器遇到加载异常时也应保留内容、清理本次已创建的结构，随后可以重试。

## 本轮自动检查

`gradlew.bat build --offline` 会编译打包，并运行 `verifyModResources`。
资源检查覆盖 JSON 语法、中英文翻译键一致性、直接使用的模组翻译键及旧命名空间残留。
这些检查不覆盖运行时动态拼接的翻译键，也不验证物理效果与实际动能网络。
